# Внешняя статистика для вопросов: какие источники брать

Исследование от 2026-10-26. Патч по нашему снимку: **7.41f** (`scripts/data/dota/manifest.json`).
Нужно найти, откуда брать данные для трёх вещей:

1. **Винрейт героев на конкретном буквенном патче** (7.41f, а не просто 7.41): по рангам и по всем рангам сразу,
   в абсолютных цифрах, чтобы героев можно было сравнивать.
2. **Популярность героев** (число игр или доля пиков): (а) за последний месяц, (б) за всё время.
3. **Популярность предметов** (как часто покупают или используют): (а) за последний месяц, (б) за всё время.

Вывод сразу (2026-10-26): **из этой среды нельзя было достать ни один живой источник статистики** —
все хосты отклоняла сетевая политика. **С 2026-10-27 OpenDota открыт** и снимок снят (раздел 1);
STRATZ по-прежнему недоступен (Cloudflare + токен). Ниже описано, что даёт каждый источник. Это
установлено по исходному коду (OpenDota открыт), по схеме API (STRATZ) и по документации и
поисковой выдаче. Описан и рабочий путь: снимок снимается **вне этой среды** и коммитится в
репозиторий так же, как сейчас снимок dotaconstants.

| Хост | Результат на 2026-10-27 |

Что выяснилось по схеме `/explorer` (запросом к `information_schema`, а не по исходникам):
`public_matches(match_id, match_seq_num, radiant_win, start_time, duration, lobby_type, game_mode,
avg_rank_tier, num_rank_tier, cluster, radiant_team int[], dire_team int[])` — хранится ровно 12 месяцев.
Таблицы `public_player_matches` нет; `matches` / `player_matches` — **только матчи лиг** (~740 за 30 дней),
поэтому покупки пабликов через `/explorer` недоступны. `avg_rank_tier` не бывает больше 75: ранга 8
(Immortal) нет ни в `public_matches`, ни в `/heroStats` (`8_pick = 0`). Ранговый All Pick —
`lobby_type = 7, game_mode = 22` (~477 тыс. матчей в сутки). Агрегат по героям за холодные сутки не
укладывается в тайм-аут 15 с, кусок 6 ч — 3–8 с.

## 3. Даты буквенных патчей: окно 7.41f определяем сами, и это воспроизводимо

`patch.json` из dotaconstants знает только крупные патчи: последняя запись —
`{"name": "7.41", "date": "2026-03-24T00:50:59Z", "id": 60}`. Букв там нет. OpenDota хранит в
`match_patch` и отдаёт в `/constants/patch` тоже только крупные патчи. Значит, ни один источник с
фильтром «patch» у OpenDota буквенный патч не отделит.

Даты букв можно восстановить по истории `dotabuff/d2vpkr`. Мы уже закрепляем этот репозиторий в
манифесте. Коммит, в котором в
`dota/resource/localization/patchnotes/patchnotes_english.txt` впервые появляются ключи
`DOTA_Patch_7_41x_*`, — это выход патча в клиент. Проверено blobless-клоном:

| Патч | Первый коммит d2vpkr с ключами | Время (UTC) | Сверка |
|---|---|---|---|
| 7.41a | `62894e2` | 2026-03-27 22:20 | — |
| 7.41b | `c9c2139` | 2026-04-07 22:20 | — |
| 7.41c | `9253fa1` | 2026-05-06 22:20 | — |
| 7.41d | `5fe586b` | 2026-06-05 01:00 | D2PT: 7.41d вышел 5 июня 2026 |
| 7.41e | `ca9626f` | 2026-07-31 00:20 | TI 2026 (13–23 августа) шёл на 7.41e |
| **7.41f** | **`969480b`** | **2026-09-15 19:00** | Liquipedia: 7.41f вышел 2026-09-15 |

Оговорка: d2vpkr забирает обновления с шагом около 20 минут, поэтому начало окна известно с
точностью примерно ±1 ч. Безопасно отступать от этой отметки 24 ч: окно 7.41f брать с
**2026-09-16T19:00Z**. Это стоит встроить в `fetch_dota_data.py`: писать в манифест
`patch_started_at` и sha коммита, который её подтверждает.

## 4. Источники подробно

### 4.1 OpenDota (api.opendota.com)

Исходники открыты: проверено по `odota/core@86e0930` (2026-10-24).

- **`GET /api/heroStats`**: сумма счётчиков в Redis **за последние 7 суток по UTC**
  (`svc/api/spec.ts`: цикл `for (let i = 6; i >= 0; i -= 1)`, ключи
  `${heroId}:${tier}:${name}:${startOfDay}`). Поля: `1_pick/1_win … 8_pick/8_win` (ранг = средний ранг
  матча / 10: 1 = Herald … 8 = Immortal), `pub_pick/pub_win` (все «значимые» паблики, то есть
  сбалансированный режим и лобби, длиннее 6 минут), `turbo_picks/turbo_wins`, `pro_pick/pro_win/pro_ban`
  (лиги premium и professional), `pub_pick_trend` (7 дневных значений). Кэш 60 с. **Выбрать патч
  нельзя**: через 7 дней после патча окно целиком внутри него, но это всё равно скользящее окно.
- **`GET /api/explorer?sql=…`**: произвольный SQL к read-only реплике Postgres, `statement_timeout`
  15 000 мс. Подходит таблица `public_matches(match_id, start_time, radiant_win, avg_rank_tier,
  num_rank_tier, lobby_type, game_mode, radiant_team int[], dire_team int[])`, индексы по
  `start_time`, `avg_rank_tier` и GIN по составам команд. **Хранится 12 месяцев**
  (`svc/cleanup.ts`: `DELETE … interval '12 month'`). Доля выборки задаётся
  `PUBLIC_SAMPLE_PERCENT` (по умолчанию 100, значение на проде неизвестно). Предметов в
  `public_matches` нет. Пример запроса для окна 7.41f (из-за тайм-аута может понадобиться дробить
  по дням):
  ```sql
  SELECT h AS hero_id, count(*) AS games,
         sum(CASE WHEN (h = ANY(radiant_team)) = radiant_win THEN 1 ELSE 0 END) AS wins
  FROM public_matches, unnest(radiant_team || dire_team) AS h
  WHERE start_time >= 1789585200 /* 2026-09-16T19:00Z */ AND start_time < :fetched_at
    AND lobby_type = 7 AND game_mode = 22   -- ranked all pick
  GROUP BY h ORDER BY games DESC;
  ```
  Ранги — `floor(avg_rank_tier/10)`.
- **Предметы**: `/heroes/{id}/itemPopularity` берёт последние 100 **разобранных** матчей героя
  (`svc/util/queries.ts`, `LIMIT 100`). `/scenarios/itemTimings` — только предметы стоимостью от
  1400, по таймингам, строки старше 4 недель удаляются (`MAXIMUM_AGE_SCENARIOS_ROWS: "4"`), только
  разобранные матчи. Для популярности предметов в пабликах в целом это не годится.
- **Доступ**: без ключа. По исходникам: `NO_API_KEY_PER_MIN_LIMIT: 60` в минуту,
  `API_FREE_LIMIT: 3000` в день, с ключом 300 в минуту, оплата сверх бесплатного лимита по единицам
  `API_BILLING_UNIT: 100` вызовов. Это значения по умолчанию в `config.ts`, на проде могут отличаться;
  в посте блога 2018 года — 50 000 в месяц. Нам хватит нескольких десятков вызовов на снимок. Код под
  MIT, данные — из публичного Steam API. Явного запрета на хранение производных цифр мы не нашли
  (сайт docs.opendota.com не открылся, проверить там не удалось).
- **Снимок**: сохранять сырой JSON ответа и текст SQL. `/heroStats` воспроизвести нельзя (окно
  скользит), поэтому сохранённый ответ и есть источник истины. Запрос к `/explorer` с закрытым
  окном (оба конца в прошлом) воспроизводим, пока данные не старше 12 месяцев.

### 4.2 STRATZ (api.stratz.com/graphql)

Схему видели в чужом репозитории `tanmay763/dota-analyst@1c3d15d` (2026-10-08),
`.claude/skills/stratz-analysis/references/stratz_schema.graphql`.

- **`heroStats.winHour / winDay / winWeek / winMonth / winGameVersion`**. Аргументы: `heroIds, take,
  skip, bracketIds: [RankBracket], positionIds, regionIds, gameModeIds, groupBy`. Строки:
  `{heroId, matchCount, winCount, (day|week|month|gameVersionId), durationMinute}`. `RankBracket`:
  `UNCALIBRATED, HERALD … IMMORTAL`. Без `bracketIds` — все ранги.
  - `winGameVersion` даёт срез по версии игры, а `constants.gameVersions {id name asOfDateTime}` —
    список версий. Есть ли там отдельные id для буквенных патчей, **проверить не удалось** (нужен
    токен). По нашим сведениям STRATZ заводит версии на буквы, но надо проверить первым же запросом.
    Если нет — окно 7.41f собираем из `winDay`, суммируя дни с 2026-09-16.
  - Недели в STRATZ начинаются в **четверг** 00:00 UTC. `matchCount` считает слоты героев: сумма по
    героям делённая на 10 даёт число матчей. Средневзвешенный винрейт по рангу ровно 0,5 — удобная
    проверка.
- **Предметы**: `heroStats.itemFullPurchase(heroId: Short!, week, bracketBasicIds, positionIds)` —
  строки по `itemId × instance × time(минута) × week`. Чтобы получить «самые покупаемые предметы
  вообще», нужно ~127 запросов (по одному на героя) и сумма `matchCount`. Без `week` отдаётся текущая,
  ещё не закрытая неделя. Срезов «за месяц» и «за всё время» нет — собираются из недель, и глубина
  истории неизвестна.
- **Доступ**: Bearer-токен (JWT), его выдают после входа на stratz.com через Steam. По посту STRATZ
  2021 года: базовый токен около 2000 запросов в час, Individual — 4000 в час и 20 000 в день;
  актуальных лимитов не нашли. Ответ 403 `A bearer token is required` означает просроченный или
  неверный токен. Условия использования (кэширование, распространение) прочитать не удалось:
  stratz.com заблокирован.
- **Живые данные (из вторых рук)**: в том же репозитории лежит отчёт от 2026-09-29, построенный по
  `winWeek`, ранговый All Pick, неделя с четверга 2026-09-10. Пример: Immortal — Bounty Hunter
  **56,9% (19 814 пиков)**, Enigma 56,8% (7 491). Herald — Spectre 56,9% (4 627). Объём за 8 недель:
  Legend 55,3 млн слотов, Immortal 11,6 млн. Эта неделя (10–17 сентября) захватывает и 7.41e, и
  7.41f: наглядный пример того, почему по неделям нельзя считать буквенный патч.
- **Важный риск**: в том отчёте записано, что 2026-09-29 почасовая и недельная статистика STRATZ
  обрывалась на 2026-09-17 (отставание около 2 недель), а дневные объёмы с 2026-09-03 упали примерно
  в 5 раз. Нужно проверить, обновляются ли данные сейчас, прежде чем делать STRATZ основным
  источником.

### 4.3 Dotabuff (www.dotabuff.com)

- API нет, только HTML. Страницы:
  - `/heroes/winning?date=week|month|…` — винрейт и доля пиков;
  - `/heroes/played?date=month|year|all` — матчи, доля пиков, винрейт, доля банов, KDA;
  - `/heroes/meta` — по рангам;
  - `/items?date=week|month|all` — «Times used», «Use rate», винрейт.
- Пример из поисковой выдачи (дата снимка неизвестна): `items?date=all` — Power Treads
  **10 960 061 997** использований, доля 30,95%, винрейт 49,02%. `items?date=week` — Aghanim's Shard
  22 625 172, 30,32%, 56,19%. `heroes/played?date=all`, верхняя строка — 2 285 171 матч, 27,64%
  пиков, 51,30%. Порядки чисел у героев и предметов не сходятся: это выборки, абсолютные числа
  разных страниц не сравнимы.
- Фильтр `date=patch_7.41` встречается в выдаче. Есть ли буквенные патчи, не подтверждено.
- Ограничения: сайт за Cloudflare, условия использования Elo Entertainment Inc. найти не удалось
  (нашлась только Privacy Policy от 2018 года). Сторонние «скраперы Dotabuff» рекламируют обход
  капчи — сам сайт автоматический доступ не приветствует. **Регулярный скрапинг не рекомендуем.**
  Допустимо открыть страницу руками и записать несколько значений с датой.
- Это **единственный найденный источник «за всё время»** и для героев, и для предметов.

### 4.4 Dota2ProTracker (D2PT) и прочие сайты

- D2PT: «данные 7000+ MMR и про-матчей, дополнены через API Imprint и STRATZ». Есть страницы
  патчей (`/patches/7.41d`) с датами и баннер «Patch 7.41f Released — stats available». Публичного
  API нет, сопоставление матчапов требует входа. Годится только для вопросов про хай-MMR и про-сцену.
- dotacoach.gg: страницы `/heroes/meta/7.41f` с буквенным патчем, например «Pudge 30,2% пиков».
  Но источник данных не указан, страницы противоречат друг другу, а служебная страница говорит
  «stats based on patch 7.41e». Как источник истины не годится.
- Spectral.gg — хай-MMR. windrun.io — Ability Draft. Оба не подходят.
- dota2protips.com в методологии прямо пишет: винрейты и пики по рангам берёт у STRATZ, предметы —
  у OpenDota. Индустрия опирается на те же два API.

### 4.5 Valve / Steam Web API

- `IDOTA2Match_570/GetMatchHistoryBySequenceNum` отдаёт поток всех публичных матчей: герои, победа,
  `item_0..5` в конце матча. Нужен ключ Steam. Условия Steam Web API (steamcommunity.com/dev/apiterms):
  **100 000 вызовов в день**. Статистику пришлось бы собирать самим (по сути, свой OpenDota):
  непропорционально дорого. Рангов в ответе нет. В 2024 году `GetMatchDetails` уже ломался на
  несколько недель (issue ValveSoftware/Dota2-Gameplay#17910).
- `www.dota2.com/datafeed/patchnoteslist` даёт официальные даты буквенных патчей, но хост
  заблокирован. Замена — d2vpkr (раздел 3).

### 4.6 Датасеты

Свежих дампов публичных матчей нет. OpenDota выкладывал дампы в 2015 и 2017 годах (матчи
2011–2016) на Academic Torrents; Kaggle-наборы тоже старые (около 2017). Для патча 7.41f бесполезно.

## 6. Формат снимка

По аналогии с `scripts/data/dota/manifest.json`: сырые ответы как есть, рядом нормализованная таблица
и манифест. Скользящие окна воспроизвести нельзя, поэтому **сырой ответ и есть источник истины**,
а запрос хранится для аудита и повторного съёма.

```
scripts/data/stats/
  2026-10-26/                         # дата съёма (UTC) = id снимка
    manifest.json
    raw/opendota_explorer_hero_wr_7.41f.json
    raw/opendota_heroStats.json
    raw/stratz_winDay_<bracket>.json
    raw/stratz_itemFullPurchase_<heroId>.json
    raw/dotabuff_items_all.html       # ручная фиксация
    heroes.json                       # нормализовано
    items.json
```

`manifest.json`:

```json
{
  "snapshot_id": "2026-10-26",
  "game_patch": "7.41f",
  "patch_started_at": "2026-09-15T19:00:24Z",
  "patch_evidence": {"repo": "dotabuff/d2vpkr", "commit": "969480b",
                     "file": "dota/resource/localization/patchnotes/patchnotes_english.txt",
                     "key": "DOTA_Patch_7_41f_*"},
  "datasets": [
    {
      "id": "hero_wr_patch",
      "source": "opendota",
      "endpoint": "https://api.opendota.com/api/explorer",
      "query": "SELECT … WHERE start_time >= 1789585200 AND start_time < 1792972800 …",
      "window": {"from": "2026-09-16T19:00:00Z", "to": "2026-10-26T00:00:00Z", "kind": "patch"},
      "filters": {"lobby_type": 7, "game_mode": 22, "brackets": "1..8 + all"},
      "fetched_at": "2026-10-26T12:00:00Z",
      "http_status": 200,
      "raw_file": "raw/opendota_explorer_hero_wr_7.41f.json",
      "sha256": "…",
      "sample": {"matches": 0, "min_games_per_hero": 0}
    }
  ]
}
```

Строка в `heroes.json`: `{hero_id, bracket, window_id, games, wins, winrate, pick_rate}`.
`winrate` пересчитывается кодом из `wins/games` — так же, как в числовых вопросах число не пишет
модель.

Правила для вопросов на этих данных:

- В тексте вопроса всегда указано окно и источник: «по данным OpenDota, патч 7.41f, все ранги, на
  26.10.2026». Вопрос хранит `snapshot_id` и `dataset.id`.
- Отдавать предпочтение **сравнению и порядку**, а не точному проценту: у героя A винрейт выше, чем
  у B, если разница ≥ 1,5 п.п. и у обоих ≥ 5000 игр в окне. Для «ближе всех» — доля пиков или
  винрейт с шагом, при этом выборка ≥ 20 000 игр.
- Срок годности: вопросы с окном `patch` устаревают с выходом 7.41g (fetch покажет новый ключ
  `DOTA_Patch_7_41g` в d2vpkr), вопросы «за месяц» — через 30 дней. «За всё время» живут дольше,
  но пересматриваются вместе со снимком.

## 7. Открытые риски

1. **Сеть.** ~~Из этой среды все источники статистики закрыты (403).~~ С 2026-10-27 OpenDota открыт,
   снимок снят (`scripts/data/stats/2026-10-27/`). STRATZ — Cloudflare и токен, Dotabuff и D2PT — 403.
   Значения STRATZ и Dotabuff в этом отчёте — по-прежнему из схемы, чужого отчёта и поисковой выдачи.
2. **Свежесть STRATZ.** По стороннему отчёту на 2026-09-29 данные обрывались на 2026-09-17, объёмы
   упали примерно в 5 раз. Причина неизвестна: изменения у Valve? нагрузка?
3. **Буквенные версии STRATZ** не проверены: неизвестно, отдаёт ли `gameVersions` 7.41f отдельно.
4. **Лимиты и условия.** Настоящие лимиты OpenDota на проде, условия STRATZ (кэш и распространение)
   и Dotabuff прочитать не удалось: сайты заблокированы. Перед публикацией цифр в игре (репозиторий,
   скорее всего, публичный — GitHub Pages) прочитать ToS. Хранить сырые ответы в публичном репозитории
   рискованнее, чем производные числа; возможно, сырые данные стоит держать вне git или в приватном
   хранилище.
5. **Тайм-аут `/explorer` 15 с**: агрегат по 40 дням пабликов не укладывается (даже сутки «холодных»
   данных — тайм-аут). Решено: `fetch_stats.py` режет окно на куски по 6 ч (3–8 с каждый), кусок с
   тайм-аутом делит пополам, каждый кусок сохраняет в `raw/explorer_hero/`.
6. **Выборка OpenDota**: `PUBLIC_SAMPLE_PERCENT` на проде неизвестен. Абсолютные числа игр могут
   быть долей реальных. Винрейты и доли от этого не страдают, а «сколько игр сыграно» — страдает.
   Абсолютное число игр в вопросах не использовать.
7. **«За всё время»** есть только у Dotabuff и только вручную. Цифры у героев (~2,3 млн) и у
   предметов (~11 млрд) несопоставимы по методике — использовать лишь порядок внутри одной страницы.
8. **Граница патча**: d2vpkr даёт время с точностью около ±20 мин–1 ч. Отступ 24 ч закрывает эту
   неточность и исключает первые часы, когда игроки ещё не обновились.
9. **Определение ранга**: у OpenDota ранг — средний по матчу (`avg_rank_tier`), у STRATZ — свой
   `bracket` матча. Цифры по рангам между источниками не смешивать.
