## 1. Свежесть и глубина: STRATZ рваный

Самое важное: у разных полей разная свежесть. Проверено на 2026-10-27.

| Поле | Что даёт | Есть данные | Годится для |
|---|---|---|---|
| `heroStats.winGameVersion` | винрейт по версии игры | **застрял на 7.40 (id 181)**, 7.41* нет вообще | ничего |
| `heroStats.winWeek` | по неделям (с четверга), ранги `HERALD…IMMORTAL`, позиции | 8 недель, **последняя — 2026-10-01** (до 10-08) | винрейт на 7.41f: 3 целые недели 09-17…10-08, ~10,6 млн матчей |
| `heroStats.winDay` | по дням | 30 дней, **последний — 2026-10-10**; с фильтром рангового AP только 10-03…10-10 | не используем |
| `heroStats.winMonth` (`take: 1000`) | по месяцам | **2014-09 … 2026-08**, 133 месяца, дыра 2024-10…2025-08 | пики «за год» (2025-09…2026-08, 156 млн матчей) и «за всё время» (1,6 млрд матчей) |
| `heroStats.winHour` | по часам | только последние ~8 часов | не нужен |
| `heroStats.stats(week)` | средние за матч: урон, хил, станы, стаки, курьеры, диспелы… | **свежие**, текущая неделя (2026-10-22) | «кто в среднем больше всех…» |
| `heroStats.itemFullPurchase(heroId, week)` | покупки предмета по минутам, `instance` 0 = первая покупка, 1 = вторая | **свежие**; недели **2025-10-23 … сейчас без пропусков** (+2024-01…2024-10) | предметы за патч, 4 недели, год, на конкретном герое |
| `itemStartingPurchase`, `itemBootPurchase` | стартовые предметы и ботинки | текущие | «что берут на старте» |
| `itemNeutral` | нейтралки | **пусто** | — |
| `heroVsHeroMatchup` | синергия с героем и преимущество против | текущие | контрпики, лучшие пары |
| `laneOutcome` | исход линии против героя: победа, ничья, поражение, разгром | текущие | «против кого X проигрывает линию» |
| `talent` | частота и винрейт каждого таланта | текущие | «какой талант на 10 берут чаще» |
| `banDay` | баны по дням | **2021-02 … сегодня** (игнорирует `heroId`, отдаёт всех) | «кого банят чаще всего» за патч, год, всё время |
| `constants.patchNotes` | патчноуты | для 7.41f пусто (у нас есть `patchnotes.json` из dotaconstants) | — |
| `constants.gameVersions` | буквенные патчи с датами | 7.41f = id 190, `asOfDateTime` 2026-09-15 | сверка дат |

## 2. Предметы

`itemFullPurchase` отдаётся **только по одному герою** и одной неделе: «предметы вообще» = сумма по
127 героям. Год = 127 × 52 ≈ 6600 пар, по 8 пар в запросе ≈ 830 запросов (~20–30 минут, кэш докачивает).

- Метрика — **первые покупки** (`instance 0`): «сколько раз предмет купили хотя бы раз за матч».
  Повторные (`instance 1`: Perseverance, Healing Lotus, Wraith Band) лежат в поле `second`.
- **Знаменателя нет**: число матчей героя в ответе не приходит, а `winWeek` отстаёт и, возможно, считает
  другие режимы. Поэтому формулировка — сравнение предметов («что покупают чаще»), доля среди всех
  покупок, порядок; не «в X% матчей».
- Мелкие корзины по минутам, видимо, отрезаны — суммы слегка занижены, порядок надёжен.
- **Ботинок и расходников в `itemFullPurchase` нет** (Tango, варды, TP, Smoke, Gem). Ботинки — отдельно
  `itemBootPurchase` → `boots.json` (недели патча): это скорее «итоговые ботинки» — Boots of Speed 24,8 млн
  у тех, кто не собрал улучшенные; Power Treads 30,0 млн, Arcane 22,9, Phase 16,2, Travel 11,0, Tranquil 10,7.
  Расходники на старте — `starting.json` (Tango, Iron Branch, Magic Stick…), без окна (текущая выборка).
- Окна в `items.json`: `items_patch` (недели 7.41f), `items_4w`, `items_year` (52 недели); по всем героям
  (`hero_id: null`) и по каждому герою (строки с ≥ 50 покупками).
- `items_weekly.json` — по неделям для трендов («что стали покупать чаще после 7.41f»).

Снято: 52 недели (2025-10-23 … 2026-10-15) × 127 героев, 851 запрос, ~15 минут; 116 предметов.

## 3. Друзья

`player(steamAccountId)` отдаёт всю историю матчей (`matches(request: {take: 100, skip})`, проверено до
4321-го матча, с 2022 года) со всеми полями игроков: герой, K/D/A, урон, хил, предметы на конец игры,
нейтралка, позиция, награда (MVP / TOP_CORE / TOP_SUPPORT), фид, ливы, партия (`partyId`). Агрегаты:
`heroesPerformance` (по умолчанию **последние 10 матчей** — нужен `request: {take: 100000}`),
`matchesGroupBy(groupBy: HERO, withFriendSteamAccountIds: [...])` — герои и винрейт «вместе с другом».
`groupBy: STEAM_ACCOUNT_ID_WITH_TEAM` без конкретного id не работает («must supply a SteamAccountId») —
друзей ищем сами по `partyId` в матчах.

**Анонимные профили** (в клиенте Dota 2 выключено «Expose Public Match Data» — это настройка игры, не
Steam; `steamAccount.isAnonymous = true`): STRATZ не отдаёт их историю и агрегаты по героям («Player Id is
missing or anonymous»), **но отдаёт `matchCount` и `winCount`** — по ним видно, какую долю игр мы покрываем. Но в матчах, где они играли с открытым игроком, они видны
полностью (id, ник, герой, статистика). Поэтому `fetch_friends.py` считает их статистику **по матчам
компании** (`coverage: group_matches`); сольные игры анонимов недоступны — обходить флаг не пытаемся.

На 1101588971 (выбрудок, ранг 63, 4321 матч с 2022-10): 11 друзей с ≥ 30 играми в одном пати; 4 открытых
(Блох Иглы, ональный трахадоr, DUPEHb + сам) и 8 анонимных (гнилой кулич, Rocinante, Питахайль, гибридная
швваль…). Всего 10 841 матч компании 2020-03 … 2026-10. **Половина — Турбо** (5002), поэтому сводка в
трёх срезах: `all`, `normal` (без Турбо), `turbo` — в Турбо другие цифры (рекорд 46 убийств и GPM 2626 —
Турбо).

Сверка: «вместе» по нашему подсчёту совпало с `matchesGroupBy(withFriendSteamAccountIds)` STRATZ
(я + Блох — 1119, я + Rocinante — 1057).

**Пересъём 2026-10-29: Rocinante открыл профиль.** Полный съём заново (на Windows-машине не было `matches.jsonl`,
205 запросов): 13 688 матчей компании 2020-03 … 2026-10-28, открытых теперь 5 (+ Rocinante, своя история 3131 игра;
в `metrics.json` рейтинг 0 → 2743, Турбо 0 → 1385). Выборка «в пати с открытым» у остальных выросла (выбрудок,
рейтинг 924 → 1188), у анонимов — едва (гнилой кулич 533 → 541, Питахайль 385 → 387: их игры с одним Rocinante
раньше не было видно никому). id вопросов от этого не меняются (`fr:<тип>:<steam id>:<режим>…`); у Rocinante
меняются формулировка («в пати в рейтинге» → «в рейтинге») и ответы. Пересъём: `python -X utf8
scripts/fetch_friends.py --me 1101588971 && python -X utf8 scripts/friends_questions.py --build` (`-X utf8` —
на Windows, иначе печать кириллицы падает).

Что есть в `summary.json` (по каждому срезу): по человеку — игры, винрейт, герои (игры/винрейт),
лучший и худший герой (≥ 20 игр), средний KDA, награды, позиции, частые предметы на конец игры, рекорды
(убийства, смерти, урон, хил, GPM, длительность — с героем и датой), фид и ливы; по парам — игр вместе,
винрейт вместе, частые связки героев; стаки — составы пати и их винрейт.

Ограничения (проверено субагентом на данных): у 4 из 12 человек почти нет обычных игр (7–107 за всю
историю, ни одной за 90 дней) — вопросы про них не задавать; общие винрейты у всех 48–51%, MVP ~12% —
сравнения без зазора превращаются в монетку (правило: отрыв от второго места ≥ 5 п.п. для долей, ≥ 15%
для счётчиков); друг против друга 0 игр; флаг намеренного фида почти только в Турбо; награды проставлены
у ~80% обычных игр; позиции пусты у ~10%; выбросы есть (хил 119 806 на Pudge) — рекорды проверять глазами;
история DUPEHb с 2020 года — часть рекордов из старых патчей.

### Шум «восстановленной» статистики (2026-10-27)

Проверка на открытых: полная история человека против выборки «только матчи с другим открытым из компании»
(ровно так собираются анонимы). Герои с ≥ 20 игр в обеих выборках; «пары» — совпадает ли порядок двух героев
при зазоре в полной истории ≥ 5 п.п. (винрейт) и ≥ 15% (игры). Скрипт — scratchpad `noise/noise.py`.

| Кто | Покрытие | Ошибка винрейта героя (ср.) | Порядок пар: винрейт / игры | Герои ≥ 20 игр: полн → восст |
|---|---|---|---|---|
| Блох Иглы | 82% | 2,4 п.п. | 98% / 99% | 37 → 26 |
| ональный трахадоr | 68% | 3,9 п.п. | 94% / 95% | 33 → 24 |
| выбрудок | 49% | 4,7 п.п. | 89% / 90% | 34 → 22 |
| DUPEHb | 26% | 4,5 п.п. | 80% / 75% | 68 → 22 |

Анонимы (покрытие = наши игры / `matchCount` STRATZ): гнилой кулич 1363 / 2229 = **61%**, Rocinante
1669 / 4509 = **37%**, Питахайль 624 / 1655 = **38%**. Общий винрейт сходится (47,5 / 47,5; 49,4 / 51,9;
48,1 / 48,9). Героев с ≥ 20 игр в выборке: кулич 16, Rocinante 22, Питахайль 5.

Вывод: главная ошибка не случайная, а **смещение** — с компанией играют других героев (DUPEHb в целом —
Invoker, SF, Pudge, PA; с нами — Invoker, Magnus, SF; у выбрудка Kez обгоняет Leshrac). Поэтому вопросы
про анонимов (и про всех, для единообразия) формулировать **«в играх с компанией»** — тогда данные точные,
а не шумные. Оговорка: игры анонимов только друг с другом (без открытых) не видны. Винрейт героя и сам по
себе шумит (20 игр → ±11 п.п.), так что для сравнений нужны ≥ 30–40 игр и зазор ≥ 10 п.п.

### Вопросы про друзей (решено 2026-10-27)

Люди: выбрудок, Блох Иглы, ональный трахадоr, DUPEHb, Rocinante (открытые; Rocinante — с 2026-10-29), Питахайль,
гнилой кулич (анонимы).
Прототип — `scripts/friends_questions.py`: `--build` собирает `scripts/data/friends/metrics.json`
(герои по человеку, режиму и выборке, пары), `--sample N` показывает вопросы. Данные друзей коммитим
(кроме `matches.jsonl` и `state.json` — 72 МБ, в .gitignore).

Правила: вопрос про одного — открытый профиль по всей истории («в рейтинге»), аноним — игры в пати с
кем-то из открытых («в пати в рейтинге»; в одной команде с открытым аноним всегда был в его пати); срезы — рейтинг (`lobbyType RANKED`) и Турбо, не смешиваются; нерейтинговый All Pick,
Single Draft и Battle Cup (~28% не-Турбо игр) в вопросы не идут; пары аноним + аноним не
спрашиваем; отрыв лидера: счётчики ≥ 15%, винрейт ≥ 10 п.п.; винрейт — от 30 игр (пересмотрено 2026-10-29 —
пороги по типам в [system.md](system.md), «Друзья»).

| Блок | Тип | Режим | Пример |
|---|---|---|---|
| А | `hero_main` — на ком больше всего игр; ловушка — мейн другого режима | MC | «Блох Иглы: на каком из героев больше всего игр в рейтинге?» |
| А | `hero_games` — сколько игр на герое | closest | «ональный трахадоr: сколько игр на Hoodwink в Турбо?» |
| Б | `hero_wr` — лучший / худший винрейт | MC | «Rocinante: на ком лучший винрейт в Турбо?» |
| Б | `self_wr` — «знаешь ли ты себя» | MC | «Rocinante: какой винрейт на Marci в рейтинге?», шаг от выборки, ≥ 5 п.п. |
| В | `pair_games` — сколько игр вместе | closest | «выбрудок и Rocinante: сколько игр вместе в рейтинге?» |
| В | `pair_top` — с кем больше всего игр | MC | «DUPEHb: с кем больше всего общих игр в Турбо?» |

2026-10-29: ник в родительном падеже («у выбрудка», таблица `GENITIVE` в `friends.ts`), без глаголов с родом. `mode_trap` слит в `hero_main` (10 из 10
пар были дословно одинаковыми — текст и ответ, разные ключи, оба выпадали в одной игре): ловушка встаёт на место
одного из соперников, id карточек `fr:hero_main:<id>:<режим>` прежние.

Не берём: рекорды, «чья это статистика», винрейты пар и стаков, роли, предметы, день недели, MVP.

Варианты: ответ — лидер среди показанных (отрыв ≥ 15% / ≥ 10 п.п.); в вопросе нет «от 30 игр» — порог
только внутренний. Попавшие в варианты герои / люди исключаются из этого типа до конца игры (`Gen.used`).
`pair_top`: при 7 людях и 4 вариантах после первого вопроса остаётся 2 кандидата — тип даёт ровно один вопрос
на срез за игру, и в рейтинге его ответ — выбрудок у всех, кроме самого выбрудка (компания собрана вокруг него). Вход: выбор «кто ты» со скипом; при каких условиях
включать категорию — не решено.

### Средние за матч: разбор подкатегорий (2026-10-27)

Источник — `hero_avg.json` (`heroStats.stats(week)`, 5 недель 09-17…10-15, свежее `winWeek`; ~0,5–1 млн
матчей на героя — статистического шума нет, важен только зазор между вариантами). Числа — за матч, не за минуту.

**Как собирать вопрос.** Для поля задан пул: верх (top N), низ (bottom N) или весь список. Из пула берём
4 случайных героя; если лидер (у «кто меньше» — последний) отрывается от второго меньше чем на 10%,
пересобираем. Ниже — доля случайных четвёрок, которые проходят порог с первой попытки (симуляция):

| Поле | Пул | Пример верха | Проходит ≥ 10% |
|---|---|---|---|
| Хил союзникам `healingAllies` | верх 20 | Oracle, Io, Dazzle, Warlock, Chen | 81% |
| Урон героям `heroDamage` | все 127 | Ember, Zeus, Leshrac, Necrophos | 57% |

Хил союзникам: заметный хил (≥ 500 за матч) только у 20 героев, у 43 из верхней половины — меньше сотни.

**Механика выбора (часть обновления).** Вопросы в игре не повторяются. В STRATZ-подкатегориях герой, уже
попавший в варианты, исключается из этой подкатегории до конца игры. Порядок: сначала проверить, что в пуле
осталось ≥ 4 неиспользованных героев (иначе взять другую подкатегорию); затем искать четвёрку с отрывом
лидера ≥ 10% не фиксированным числом попыток, а перебором; если такой нет — снять гейт.

### Контрпики и таланты (решено 2026-10-27)

Данные перекачаны за недели патча (`per_hero_patch_weeks`): медиана 17 тыс. матчей на пару героев
(было ~2 тыс. в выборке STRATZ по умолчанию), стат. ошибка преимущества ~0,4 п.п.

**Контрпики.** Метрика — преимущество STRATZ (`synergy` в `vs`: винрейт против героя с поправкой на силу
обоих), не сырой винрейт. Один бакет: все соперники с ≥ 5000 совместных матчей (медиана 116 на героя;
у Chen, Batrider, Elder Titan пул мал — не задавать). Вопросы «против кого X выигрывает реже / чаще всего»,
отрыв лидера от второго ≥ 2,5 п.п. Случайная четвёрка проходит гейт редко (6–8%), поэтому перебор
обязателен; возможных ответов на героя — медиана ~60. Типичный разброс матчапов узкий (Juggernaut −3,2…+3,6;
Invoker −3,7…+3,1; исключение Anti-Mage: Meepo −7,0, Medusa +10,9). Синергию не берём.

**Таланты.** 4 варианта — оба таланта 20 уровня и оба 25-го; «какой берут чаще / реже всего» по доле
внутри своей пары (пара = 100%). Отрыв лидера от второго ≥ 10 п.п. есть у 65 из 125 героев, ≥ 5 п.п. —
у 92. Тексты сейчас английские (`talents.json`); русские — из `abilities_russian.txt`, но там шаблоны
вида `+{s:bonus_AbilityChannelTime} сек. действия Dismember` — нужна подстановка чисел из файлов героев.

### Баны (проверено 2026-10-27)

`banDay` — **не рейтинг**: ~4 тыс. банов в будни и 50–65 тыс. по субботам (Battle Cup / Captains Mode),
в рейтинге было бы на порядки больше. Для вопросов не берём.

Рейтинговые баны есть в самих матчах: `match(id) { pickBans }` у распарсенных матчей. `matches(ids:)` требует
прав админа, поэтому `fetch_stratz.py --only rankedbans` берёт случайные id в окне патча и спрашивает
`match(id)` через алиасы по 100 (≈ 36% id дают рейтинговый All Pick с драфтом). Снято 10 019 матчей
(429 запросов, ~4 мин) → `bans_ranked.json`: **доля матчей, где герой забанен** — тот самый процент.

- В рейтинге 16–21 успешный бан на матч (16 — в 67% матчей); STRATZ отдаёт только прошедшие баны, так что
  «заполнение слотов» не посчитать, но оно и не нужно — доля матчей с баном считается напрямую.
- Верх 7.41f: Pudge 59%, Phantom Lancer 43%, Lion 37%, Sniper 36%, Axe 33%, Anti-Mage 32%, OD 31%;
  медиана 9%, низ ~5% (Elder Titan, Gyrocopter, Batrider). Погрешность на 10 тыс. матчей ≤ 1 п.п.
- Ранг матча STRATZ в этих ответах не отдаёт (`averageRank` пуст) — все ранги вместе.
- Форматы: «кого банят чаще всего» (верх 30, отрыв ≥ 2,5 п.п. — случайная четвёрка проходит в 78%),
  closest «в каком % матчей банят Pudge?».

### Решения по пластам (2026-10-27)

- **Средние за матч — берём** (список зафиксирован выше). Каждую подкатегорию разбирать отдельно: что сталкиваем. Варианты — близкие
  по значению, но не обязательно соседние, и из одной части списка (верх или низ), иначе угадывается кор.
  Хил — только верх (низ — шум «хилит / не хилит»); внутри верхней части берём случайных, чтобы разница
  не была стабильно в 1%. Урон — один большой бакет, сталкиваем всех.
- **Контрпики — берём, синергию нет** (решено: один бакет, преимущество, гейт 2,5 п.п. — см. выше).
- **Таланты — берём:** таланты 20 и 25 уровня, «какой берут чаще / реже всего» (см. выше).
- **Баны — только современные**, в процентах от матчей: есть, см. «Баны» выше (`bans_ranked.json`).
- Лайнинг, стартовые предметы, тренды, позиции — мимо.

**Тема и веса** — в `server/src/game/questions/categories.ts`, банк их больше не хранит (2026-10-30): тема — «Герои /

## 6. Открытые вопросы

1. **Знаменатель предметов** (проверено 2026-10-30, ответ — «точного нет»). У `itemFullPurchase` и `stats` одни и те же
   аргументы (`heroId`, `week`, `bracketBasicIds`, `positionIds`), но выборки разные. Tidehunter, неделя 2026-09-24:
   `stats.matchCount` 101 733, а одних первых покупок Blink — 116 754 (больше матчей); `winWeek` все режимы 388 967,
   рейтинг 238 242, обычный All Pick 48 247, Турбо 101 868. На той же неделе первые покупки лучшего предмета героя —
   ≈ половина его рейтинговых матчей у всех трёх проверенных (Blink у Tidehunter 49%, Battle Fury у Anti-Mage 51%,
   Blink у Pudge 48%) — выборка покупок около половины рейтинга (видимо, только разобранные матчи), а не все матчи.
   Перезапрос с одинаковым окном поэтому не помогает: доля «покупки / рейтинговые матчи» за одни и те же недели
   занижена примерно вдвое. В игре (closest «В каком проценте матчей на Axe покупают Blink Dagger?») — покупки за
   5 недель патча (`items_patch`) к рейтинговым матчам героя за 3 недели (`hero_wr_patch_weeks`): 5 / 3 недели почти
   компенсируют половинную выборку, получается **оценка**; пары выше 95% выкидываются (Blink у Tidehunter — 102%), в
   comment так и написано. Если найдётся честный знаменатель (число матчей в выборке покупок) — пересчитать.
2. **Свежесть `winWeek`/`winMonth`.** Перепроверять при каждом снимке: если догонят, окно патча расширится.
3. **Условия STRATZ.** Публиковать производные числа в игре, сырые ответы в публичный репозиторий не класть:
   `stats/*/stratz/raw/` (~24 МБ) — в `.gitignore`, сборщику банка не нужны.
4. **Друзья в игре.** Выбор «кто ты» при входе (со скипом); категория включается, когда опознаны ≥ 2 человека; вопросы только про опознанных ([system.md](system.md), раздел 6).
   Данные друзей можно коммитить (решено 2026-10-27).
5. **Анонимы.** Статистика только по играм с компанией — в тексте вопроса так и писать (покрытие 37–61%,
   см. «Шум восстановленной статистики»). В вопросы про друзей берём: выбрудок, Блох Иглы, DUPEHb,
   ональный трахадоr, Питахайль, гнилой кулич, Rocinante; остальных нет.
