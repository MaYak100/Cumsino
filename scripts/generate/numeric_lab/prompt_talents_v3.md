Ты составляешь вопросы про таланты героев для викторины по Dota 2. Играют опытные, серьёзные игроки: тысячи часов, знают механики, но таланты наизусть не учат.

Тебе дают 10 героев: их способности и таланты (`talents`: id, уровень 10/15/20/25, текст, вид `kind`). Вид размечен заранее:
- `stat` — голый стат без способности: «+200 Health», «+25 Attack Speed»;
- `tweak` — правка числа у способности: «-4s Meat Hook Cooldown», «+75 Vacuum AoE»;
- `mechanic` — талант, который меняет поведение способности: «Whirling Axes Pierce Magic Immunity», «Reincarnation Casts Wraithfire Blast».

## Что нам нужно

Вопрос «**Какой из этих талантов есть у героя?**» (`type: has`): 1 настоящий талант и 3 выдуманных.

Нам интересны только **необычные** таланты: те, что меняют то, как играется способность, и которые игрок может вспомнить, представив героя в игре. Голые статы и правки чисел («-15s Cooldown», «+40% Lifesteal») — это зубрёжка, их никто не помнит, такие вопросы не нужны.

- Настоящий вариант — почти всегда `mechanic`. `tweak` годится, только если число наглядное и вспоминается по картинке в игре (например, лишний фамильяр, лишний заряд, ещё одна цель).
- Из 10 героев выбери тех, у кого действительно есть такие таланты, и сделай **около 4 вопросов на весь запрос**, не больше одного на героя. Если у героя нет необычного таланта, пропусти его.

## Выдуманные варианты — самое важное

Три неверных варианта ты придумываешь сам (`kind: invented`, `from_talent_id: "none"`). Они должны выглядеть как настоящий механический талант этого героя:
- про способности этого героя и с опорой на то, как именно они работают (их описание у тебя есть) — не общие слова, а конкретика этой способности;
- правдоподобные: такое улучшение могло бы существовать, и опытный игрок засомневается;
- без чисел, где можно: не превращай вопрос в угадывание цифр;
- не повторяй настоящие таланты героя ни дословно, ни по смыслу, и не выдумывай то, что способность и так делает без таланта.

**Не повторяй одни и те же формулы.** «Пробивает невосприимчивость к магии», «даёт брейк», «даёт сайленс» и подобные шаблоны — не больше одного раза на весь ответ. Если подделки во всех вопросах построены по одному шаблону, игрок научится отсекать их по шаблону.

Настоящий вариант не должен выделяться длиной, конкретикой или стилем на фоне выдуманных.

## Язык

Все варианты — **по-русски**, в одном стиле, коротко, как строка таланта в клиенте. Настоящий талант переведи точно по смыслу (поле `text` у варианта `kind: real`), ничего не добавляя.
- Названия героев и способностей — по-английски, как в клиенте игры.
- Термины — игровым сленгом, как говорят игроки:

  | Не пиши | Пиши |
  |---|---|
  | оглушение | стан |
  | безмолвие | сайленс |
  | обезоруживание | дизарм |
  | обездвиживание | рут |
  | превращение | хекс |
  | разрушение пассивок (break) | брейк |
  | замедление | слоу |
  | вампиризм | лайфстил |
  | вампиризм от заклинаний | спелл-лайфстил |
  | усиление заклинаний | спелл-амп |
  | сопротивление эффектам | статус-резист |
  | сопротивление магии | маг. резист |
  | развеивание | диспел |
  | невидимость | инвиз |
  | истинное зрение | вижн |
  | критический удар | крит |
  | перезарядка | кд |

  Без изменений: «невосприимчивость к магии», «уклонение», «скорость атаки», «скорость передвижения», «кровотечение», «горение».

## Вопрос

Коротко и разговорно, по-русски: «Какой из этих талантов есть у Visage?». Уровень таланта не называй.

## Формат ответа

Объект с массивом `questions`, форма задана схемой. Везде `type: has`. В `options` ровно 4 варианта: один `kind: real` с `talent_id` героя и русским `text`, и три `kind: invented`.
